# 🌈 GBoxL1 Processing — визуализация для 8-битного синтезатора

Клиент для телеметрии грувбокса на ATmega328. Читает 26-байтные пакеты из Serial, рисует реактивную плазму на GLSL-шейдере, HUD с текущими параметрами и «пэды» нот. Звук синтезатора заходит в систему через линейный вход и мониторится через Minim.

> 🎛️ Сама прошивка и железо — в репозитории: **[GBoxL1 →](<https://github.com/Lolip-p/GBoxL1>)**

## ✨ Что показывает

- **Плазменный фон** (`plasma.glsl`) — цвет зависит от формы волны (синяя / оранжевая / зелёная), пульсирует на кик и ноты
- **Sidechain-виньетка** — темнеет по краям в такт сжатию
- **HUD**: attack / release (мс), форма волны, режим (DRUM/SYNTH), статус секвенсора
- **Индикаторы драм-машины**: KICK / SNARE / HIHAT, вспыхивают при каждом ударе
- **Пэды нот** внизу экрана — подсвечиваются, когда играет голос или sub-bass
- **Рамка экрана** — красная при записи, зелёная при воспроизведении секвенсора

## 🚀 Запуск

1. Установить **[Processing](https://processing.org/download)**
2. Установить библиотеки (Sketch → Import Library → Add Library):
   - **Minim** (звук)
3. Открыть `SynthViz.pde`, поправить порт:
   ```java
   port = new Serial(this, "COM3", 115200); // ← свой порт
   ```
5. Запуск скетча

### Про звук

Код использует `minim.getLineIn(...)` — берёт аудио с текущего источника записи системы (микрофон / линейный вход). Подключи выход грувбокса на линейный вход ПК — услышишь звук и увидишь визуализацию.

```java
in = minim.getLineIn(Minim.STEREO, 512);
in.enableMonitoring(); // ← пропускает вход на выход
```

## 🧩 Формат пакета (26 байт, little-endian)

Пакет отправляется из прошивки раз в ~16 мс (60 Гц) по UART @ 115200.

| Смещ. | Поле             | Размер | Описание                                    |
|-------|------------------|--------|---------------------------------------------|
| 0     | `magic`          | 1      | всегда `0xAA`                               |
| 1     | `waveform`       | 1      | 0=sine, 1=saw, 2=square                     |
| 2     | `drum_mode`      | 1      | 0/1                                         |
| 3     | `seq_mode`       | 1      | 0=IDLE, 1=RECORDING, 2=PLAYING              |
| 4–5   | `attack_ms`      | 2      |                                             |
| 6–7   | `release_ms`     | 2      |                                             |
| 8     | `v0_state`       | 1      | bit7 active, bit6 releasing, low bits btn   |
| 9     | `v0_env`         | 1      | амплитуда голоса 0                          |
| 10    | `v1_state`       | 1      |                                             |
| 11    | `v1_env`         | 1      |                                             |
| 12    | `sub_state`      | 1      |                                             |
| 13    | `sub_env`        | 1      |                                             |
| 14–15 | `kick_trig`      | 2      | монотонный счётчик (ловим приращение)       |
| 16–17 | `snare_trig`     | 2      |                                             |
| 18–19 | `hihat_trig`     | 2      |                                             |
| 20    | `drum_patterns`  | 1      | бит 0=kick, 1=snare, 2=hihat                |
| 21–22 | `sidechain_duck` | 2      | 0..65535, текущая глубина                   |
| 23–24 | `note_trig`      | 2      | монотонный счётчик нотных триггеров         |
| 25    | `xor_sum`        | 1      | XOR байт 0..24                              |

Синхронизация: ищем байт `0xAA`, дальше читаем ещё 25 байт, проверяем XOR. Если не сошлось — отбрасываем и снова ищем `0xAA`.
